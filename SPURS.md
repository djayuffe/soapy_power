# Signal, spur and noise-floor analysis for direct-conversion SDRs

Status: software complete and verified against synthetic truth; the controlled
hardware programme (50 Ω termination, signal generator, filter bank) has **not**
been run. This document describes what is implemented, how to use it, what it
can and cannot identify, and which measurements are still needed.

The implementation is deliberately evidence-preserving. It never writes an
automatic notch, exclusion list or calibration correction. Every classification
is a probability or a declared hypothesis, and every level is relative unless a
separate absolute calibration is supplied.

## 1. Scope and safety rules

- No radio is opened by the analysis code. The `demo` and `plan` commands are
  synthetic/software-only.
- No command in this module starts a measurement session. Use the existing
  `tools/macos_runner/queue.sh` only after explicit approval.
- No spur is silently removed from a floor estimate. Spurious bins receive an
  explicit responsibility or classification and are reported.
- When the LO diversity is insufficient, the result is `unidentifiable`, not a
  forced signal/spur label.
- All levels are relative and uncalibrated. `dB` means dB relative to the
  receiver's own floor or to a declared reference, not dBm.

## 2. Receiver model and sources

The B200/B200mini uses an AD9361/AD9364; the bladeRF x40 uses an LMS6002D.
Both are direct-conversion receivers with no internal preselector. Their
square-wave LO contains every odd harmonic:

\[
  \alpha_n = \frac{4}{\pi n}, \qquad n = 1,3,5,\dots
\]

An input at \(f_\mathrm{RF}\) therefore produces signed IF products

\[
  f_\mathrm{IF} = s\,(f_\mathrm{RF} - n f_\mathrm{LO}),
  \qquad s\in\{+1,-1\},
\]

where \(s=+1\) is the normal down-conversion, \(s=-1\) is the IQ image, and
\(n>1\) is a harmonic mixing response. The same relation is used by the tracker:
a real tone moves with slope \(-1\) against LO, an image with \(+1\), and a
3rd/5th-order response with \(\mp 3\) or \(\mp 5\).

The receiver profiles in `soapypower/spur_model.py` are:

| profile | RF range | architecture | nominal harmonics | notes |
|---|---|---|---|---|
| `b200` / `b200mini` | 70 MHz–6 GHz | AD9361/AD9364 direct conversion | 1,3,5,7 | no preselector; RX2 usual |
| `bladerf` / `bladerf-x40` | 300 MHz–3.8 GHz | LMS6002D direct conversion | 1,3,5,7 | ~50 MHz only with a transverter; XB-200 changes the path |
| `generic` | 1 MHz–6 GHz | generic direct conversion | 1,3,5,7 | fallback only |

The profiles are nominal starting points. The IQ image rejection, DC offset and
thermal coefficients are receiver-state and frequency dependent; they must be
measured for the state being analysed.

### 2.1 Sources explicitly modelled

- **Square-wave LO harmonics:** \(f_\mathrm{IF}=s(f_\mathrm{RF}-n f_\mathrm{LO})\).
- **DC offset / LO leakage:** a line at \(f_\mathrm{IF}=0\). It is masked from
  floor estimation and reported as a separate feature; it is not treated as a
  real RF signal.
- **IQ gain/phase imbalance:** \(y=cx+d\,\overline{x}\), with
  \[
    c=\tfrac12\left[(g+q\cos\phi)+j q\sin\phi\right],\quad
    d=\tfrac12\left[(g-q\cos\phi)+j q\sin\phi\right],
  \]
  where \(g=10^{\Delta G/20}\), \(q=1/g\), and \(\phi\) is the quadrature error.
  The image rejection ratio is \(|c/d|^2\).
- **Intermodulation:** two-tone products \(m f_1+n f_2\) with
  \(|m|+|n|=\text{order}\), generated by the nonlinear mixer/amplifier. The
  helper `two_tone_intermod()` enumerates them; the caller decides which fall
  in band.
- **ADC:** `quantize_iq()` provides a uniform mid-rise ADC twin with clipping
  count and step size. Quantization and clock/jitter artefacts are not claimed
  to be calibrated.
- **Temperature:** `iq_temperature_error()` gives an illustrative first-order
  drift; the calibrated floor-versus-temperature state is estimated by the
  existing Kalman/RTS smoother in `floor_estimation.floor_temperature_kalman()`.

## 3. Generative digital twin

`soapypower/spur_model.py` has two levels:

1. **Time domain** — `simulate_iq()` builds complex baseband samples from real
   RF tones, square-wave harmonics, DC, IQ imbalance, intermodulation, phase
   noise and thermal noise. An analog bandwidth argument prevents out-of-band
   products from aliasing into the digital spectrum; a 540 MHz product at a
   56 MHz sample rate is skipped, not folded to −20 MHz.
2. **Spectrum domain** — `simulate_psd()` / `welch_psd()` produce a complex
   Welch PSD. A bin averaged over \(K\) independent segments is Gamma-distributed
   with shape \(k=K\) and scale \(\theta=\mu/k\), where \(\mu\) is the mean floor.
   `spur_twin.Twin` draws the same Gamma distribution directly for fast tests.

`spur_twin.scenarios()` provides the T1–T5 matrix with known truth. The twin is
used for software verification only; it is not evidence about a physical
receiver.

## 4. Observability and fundamental limits

A single peak at \(f_\mathrm{obs}\) is compatible with many explanations:
a real source at \(f_\mathrm{obs}\), an image, or a harmonic response of any
in-band or out-of-band source. One spectrum cannot identify the cause. The
following freedoms make the problem identifiable:

- **LO diversity:** change LO by \(\Delta\). A signal moves by \(-\Delta\), an
  image by \(+\Delta\), and an \(n\)-th harmonic response by \(-n\Delta\) or
  \(+n\Delta\).
- **Gain/drive diversity:** a linear signal scales 1 dB/dB; an \(n\)-th order
  nonlinear product scales approximately \(n\) dB/dB.
- **Known filters/preselectors:** a real RF source disappears when its RF band
  is filtered; a harmonic response from an out-of-band source may not.
- **Coherent repetition:** phase-aligned repeated spectra can suppress
  incoherent spurs, but median combination has a bias that must be corrected.

`spur_inference.bayes_classify_track()` evaluates every law
\((n,s)\) under a Gaussian residual model and reports a posterior. It returns
`unidentifiable` unless there are at least three distinct LO settings spanning
four resolution bins. `slope_separation()` reports the Cramér–Rao lower bound
for the 1st-versus-3rd slope difference. There is no claim of 100 % spur
removal: thermal noise, look-elsewhere effects and unmodelled receiver states
remain.

## 5. Statistical estimators

### 5.1 Bias-free floor

The legacy floor was a dB-median. For exponential noise the median is
\(10\log_{10}(\ln 2)\approx-1.59\) dB below the mean; min-hold is much worse.
`floor_estimation.floor_estimate()` corrects the median for the bin dof and
excludes an upper tail with a declared spur probability. The new
`spur_inference.gamma_floor_posterior()` adds a conjugate inverse-gamma
posterior for the mean floor with a credible interval.

`spur_inference.mixture_floor_estimate()` fits a two-component Gamma mixture by
EM: the lower-scale component is the noise floor, the upper component collects
spurs. Every bin gets a responsibility, so the report can say how many bins
were treated as excess rather than simply deleting them. The floor level is
reported before and after this model; the difference is a diagnostic, not an
automatic correction.

### 5.2 FDR and look-elsewhere control

`floor_estimation.detect_peaks()` supports:

- `bh`: Benjamini–Hochberg false-discovery rate, the default;
- `bonferroni`: family-wise error control;
- `fixed`: the legacy fixed threshold, retained for comparison only.

`group_peaks()` merges adjacent detected bins. The report records the number of
bins tested so the look-elsewhere correction is visible.

### 5.3 Bayesian track classification

For each track, `bayes_classify_track()` computes the likelihood of the IF
residuals under each fixed law, multiplies by a declared prior, and normalizes.
The result contains the posterior for signal/image/harmonic, the best law, the
runner-up, and a `signal_probability`. The prior is explicit; a posterior of
0.99 is not a proof, only a statement conditional on the model.

A track also carries an `attribution`: normally equal to its LO-law `kind`
(`signal`, `image`, `lo_harmonic`), but a track that follows the fundamental
LO slope while its level grows like an integer power ≥2 of the drive is
attributed as `intermod`. The original `kind` stays `signal` because LO
diversity alone cannot separate a real tone from a nonlinear product at the
same IF; the drive test is what breaks the tie. `drive_kind` records
`linear`, `nonlinear-n`, or `not_available`. The report lists `intermod`
separately from `signals` and `spurs`.

### 5.4 Robust line fitting

`robust_line_fit()` starts with a Theil–Sen median slope, then runs Huber IRLS.
It is used to summarize a track when one LO visit is contaminated. The raw RMS
residual and the robust scale are both reported; the RMS includes outliers and
must not be read as an inlier uncertainty.

### 5.5 Sparse reconstruction

`ista()` implements nonnegative L1 reconstruction; `orthogonal_matching_pursuit()`
implements OMP. `build_spur_dictionary()` builds Gaussian point-spread atoms
for candidate RF frequencies and every mixing law, and
`sparse_decompose_spectrum()` returns labelled active atoms. The decomposition
is diagnostic: overlapping atoms are not calibrated amplitudes and no atom is
automatically notched.

### 5.6 Kalman floor versus temperature

The existing `floor_temperature_kalman()` models
\(y_k=c[g_k]+a(t_k)+b(T_k-T_\mathrm{ref})+e_k\), with a random-walk offset
\(a(t)\) and a weakly prior slope \(b\). It reports a slope range, NIS, and a
`confounded` flag when temperature and time are too collinear to separate.
This is the only defensible way to use the receiver's temperature telemetry;
a simple regression on an uncontrolled antenna input is diagnostic only.

### 5.7 Experiment design

`spur_design.d_optimal_offsets()` chooses LO settings by maximizing
\(\log\det(X^\top X/\sigma^2)\) for the intercept+slope line, subject to a
minimum span. `default_lo_plan()` gives a practical symmetric three-point plan.
`suboctave_filter_bank()` returns an advisory sub-octave preselector plan; it
does not drive a switch.

## 6. Pipeline

```
captures (LO, power, dof, drive, temperature)
  -> per-capture floor + normalization
  -> Gamma-mixture common floor + FDR peaks
  -> track every peak under every law s*(RF - n*LO)
  -> Bayesian posterior + robust residual + drive order
  -> signal / image / LO-harmonic / unconfirmed
  -> before/after floor report + figures
  -> JSON, no automatic exclusions
```

The implementation is `soapypower/spur_pipeline.py`:

- `make_capture()` validates one spectrum;
- `captures_from_twin()` adapts the digital twin;
- `analyze_sweeps()` runs the complete pipeline and returns strict JSON-safe
  data (`automatic_exclusions` is always empty).

## 8. Command-line usage

```sh
# Synthetic end-to-end demo, figures and T1-T5 score table.
soapy_power_spurs demo --out docs/spurs-demo

# Analyse measured captures in JSON:
# {"captures":[{"lo_hz":..., "power":[...], "if_hz":[...], "dof":...}, ...],
#  "profile":"b200", "options":{"alpha":0.001}}
soapy_power_spurs analyze captures.json --out analysis

# Experiment design: D-optimal LO settings, gain/filter sweeps, filter bank.
soapy_power_spurs plan --center 260e6 --profile b200
```

The same commands work through `tools/spur_report.py` without installing the
console script.

## 9. Synthetic validation

The demo runs T1–T5 through the real pipeline and scores the result against the
twin truth:

| test | truth | expected classification |
|---|---|---|
| T1 | 50 Ω, no external RF | no persistent peak; flat floor |
| T2 | 200 MHz tone, 9 MHz below LO | `signal`, slope −1 |
| T3 | 800 MHz tone, 3rd harmonic at 20 MHz | `lo_harmonic`, order 3, source ≈800 MHz |
| T4 | two in-band tones (254 and 271 MHz) | two signals; optional image/intermod handled explicitly |
| T5 | strong near-band neighbour (FM surrogate) | signal plus a documented image/harmonic response; true ambient FM requires a measurement near 100 MHz |

The current software run gives zero missed required features and zero kind
errors for T1–T5 at the default twin resolution. That is software verification,
not hardware evidence. The demo also prints the floor change and the
min-hold/median bias, runs a separate drive-diversity case with one linear tone
and one cubic intermodulation product, and writes the six figures. In that
drive case the linear tone is attributed `signal` (drive slope near 1 dB/dB)
and the cubic product is attributed `intermod` (drive order 3).

## 11. Controlled hardware phase (not run)

Do not start these without Ulf's explicit go-ahead. The software plan is in
`spur_design.lab_matrix()`.

| test | setup | pass criterion |
|---|---|---|
| T1 | 50 Ω input, LNA on, TX off, three LO settings | flat floor; no persistent peak; FDR false alarms within the declared rate |
| T2 | single tone at LO+9 MHz (200 MHz when LO = 191 MHz) | one `signal`; no harmonic classification; source recovered |
| T3 | 800 MHz tone, LO near 260 MHz | 3rd-order response at 20 MHz; slope ÷3; filter-on removes it |
| T4 | two tones at LO−6 and LO+11 MHz, drive sweep | two signals; any intermod product has the expected drive order |
| T5 | strong near-band neighbour (FM surrogate), filter on/off | fundamental signal; harmonic/image documented; floor preserved; true ambient FM requires a separate 88–108 MHz measurement |

Minimum procedure:

1. Confirm the receiver state and record gain, bandwidth, antenna port,
   temperature and LO mapping.
2. Measure the 50 Ω floor first; do not reuse an antenna-derived floor.
3. Use at least three LO settings spanning four resolution bins; use the
   D-optimal plan when the tuning range is constrained.
4. Repeat at two or three drive levels for the gain-order test.
5. Keep the raw captures and the report JSON; never overwrite evidence.
6. Compare the before/after floor and the classified bins, not only the peak
   list.

The 150–160 MHz anomaly remains unresolved. The implemented LO-diversity test
can distinguish a real source from a harmonic response **only if the LO is
actually moved**. A 50 Ω run and alternating ON/OFF runs are still required;
the software does not infer a cause from the existing data.

## 12. Limitations and open questions

- A single spectrum is fundamentally underdetermined; the posterior is
  conditional on priors and on the Gaussian residual model.
- LO harmonics above the configured order, mixer cross-modulation and
  unmodelled ADC artefacts are not in the dictionary.
- A source outside the RF range can still reach the mixer; the filter plan is
  advisory and the coupling path is not identified.
- Absolute calibration, noise figure and dBm are not provided. The existing
  calibration/audit modules remain the authority for those.
- Median and min-hold are retained only as documented legacy baselines. They
  are biased; do not use them for the floor-temperature curve.
- A POMDP/active-sensing policy is a future extension. The current experiment
  design is D-optimal and static; it does not adapt online.
- The demo's image/intermod cases are optional truth features: a missed
  optional feature is not counted as a pipeline failure.

## 13. Integration and pitfalls

- `sessions/.venv` needs `matplotlib`, `pypdf` and `packaging` for figures and
  merged PDFs. The analysis itself only needs numpy; SciPy is optional.
- `cm.get_cmap` is removed in current matplotlib; use `plt.get_cmap`.
- Error bars must use NaN, not `None`.
- Do not overwrite `run_session.sh` while a session is running.
- Read the status of a specific session ID; do not use `ls -t | head`.
- Results copied into the repository belong in `docs/results/<id>/` and need
  `git add -f` if the path is normally ignored.
- `edit_version` on an owner artifact must omit `shared_live`; never republish
  an old local file over the live artifact page.
- No claim about the 150–160 MHz cause is permitted before a controlled run.
